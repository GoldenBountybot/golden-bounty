## Key facts
- Endorphina server IPs to whitelist: 178.33.61.104 (cdn), 88.198.136.152 (test/edemo)
- Money: all amounts in THOUSANDTHS of a unit (1.26 USD -> 1260). Currency ISO 4217 (USD ok).
- Token: UUID v4 without dashes, 32 hex chars, generated by us per game session.
- Signature: sign = SHA1HEX( concat(param values sorted alphabetically by param NAME, excluding sign) + salt ). Calculated on NON-url-encoded values.
- Wrong signature -> respond 401 ACCESS_DENIED.
- Responses: JSON, Content-Type application/json.
- Game id format: endorphina_X@ENDORPHINA or endorphina2_X@ENDORPHINA (no -html5 suffix any more).
- Launch URL: {endo_url}/api/sessions/seamless/rest/v1?exit=<exit>&nodeId=<nodeId>&token=<token>&sign=<sign>
  (optional: profile, resetHistory). Test endo_url: https://test.endorphina.com

## Endpoints WE must expose ({ext_url} = our base)
- GET  /session?token&sign            -> {player, currency, game, nickname?}
- POST /bet    (amount,currency*,date,game*,gameId,id,nodeId*,player*,token,sign)  -> {transactionId, balance}
- POST /refund (same params as bet; id = bet id to cancel)                            -> {transactionId, balance}
- POST /win    (amount,date,gameId,id?(absent if amount=0),betSessionId*,betTransactionId*,count*,progressive*,progressiveDesc*,autocomplete*,token,sign) -> {transactionId, balance}
- POST /promoWin (amount,currency,date,id,player,promoId,promoName,game?,gameId?,token?,sign) -> {transactionId, balance}
- GET  /balance?token&sign             -> {balance}
- POST /endSession (optional, off by default)
- GET  /check?param&sign               -> {nodeId, param, sign=SHA1(nodeId+param+salt)}
- POST /bonus (only if wallet-like bonus enabled)
(* = optional params, enabled per node by manager)

## Rules
- Idempotency: same transaction id must NOT move money twice; return the same stored response.
- /refund for unknown bet id: create it as "cancelled", balance untouched; never process that bet later.
- Never return error on /win or /refund (they are retried until 200).
- /win with gameId=0 = win for a bet from a previous session.
- Zero-win /win has no id.
- Error format: {code, message} with HTTP: 401 ACCESS_DENIED, 402 INSUFFICIENT_FUNDS, 403 TOKEN_EXPIRED / LIMIT_REACHED, 404 TOKEN_NOT_FOUND, 429 NO_RETRY, 500 INTERNAL_ERROR.
- On /bet errors 401-404/429 no refund cycle; other errors/timeouts (>10s) -> refund cycle (1 + 5 retries, 10s apart).
- Retry/redelivery of unconfirmed transactions happens at next game launch.
